# KYC pipeline evidence (05 Nov 2026)

`report.md` is generated by `backend/scripts/kyc_pipeline_check.py`. The script runs the **production** pipeline (`backend/app/kyc/`) on all 47 specimen images:

bytes in memory → JPEG/PNG and size checks → red channel → blur gate → deskew → RapidOCR → field extraction with watermark clean-up → checks against the mock registries, dated `business_as_of` 2026-07-15.

It then compares each applicant's outcome with the answer key in `backend/tests/test_kyc_checks.py`, which is drafted in `evidence/ocr_spike/answer_key_draft.md`.

**Result of the local run:** all 12 applicants match, **0 false accepts**. K02 and K08 reach `checks_passed` only after the owner confirms the corrected GSTIN. Mean 4.2 s per image on a laptop CPU.

What this does **not** show:
- that the documents are genuine
- per-field accuracy against a fully hand-transcribed key (only 6 documents have been inspected by eye so far)
- behaviour on real phone photos, which are messier than these clean specimens

It is a local run, not CI.

**Observed once:** during an earlier full run inside pytest, ONNX Runtime raised "bad allocation" (out of memory) part-way through; the re-run passed. The pipeline now turns any OCR engine error into an `OCR_ERROR` refusal ("please try again") instead of a server error.

Tests:
- `backend/tests/test_kyc_checks.py`: fast, on the spike's OCR output.
- `backend/tests/test_kyc_pipeline.py`: real OCR on the 3 hardest images; all 47 with `RUN_SLOW=1`.
- `backend/tests/test_kyc_service.py`: HTTP flow, consent gate, encryption at rest, masking, repairs, deletion.
